The five-minute version

You asked for the seriously bad things. So here they are first, in plain language, before any of the nice stuff.

The one-line truth

Lattice is a genuinely clever gateway wearing a costume made of hardcoded numbers. The engine is better than it looks. The dashboard, the catalog and the telemetry are worse than they look. Right now the project is lying to you about its own health, and that is the most dangerous thing in the repo — worse than any single bug.

The five things that actually hurt

CriticalAnyone who can reach the port owns the gateway — and the keys inside it

The admin routes have no login. CORS is * by default. The OAuth status endpoint hands back the whole account object, refresh token included. The "setup all harnesses" endpoint rewrites your Claude Code, Cursor, VS Code and Kilo config files. None of it asks who is calling.

In plain EnglishImagine your house has a front door with no lock, a sign saying "keys are in the drawer", and a button that lets a stranger rearrange your furniture. The locksmith is standing right there in the code — it just was not wired up yet.

Example: a page you open in your browser can silently call http://127.0.0.1:4000/api/accounts and read the account list, or call /api/harness/setup-all and overwrite seven config files. No password needed.

Evidence: src/core/config.ts:41 · src/admin/admin-router.ts:151-204, 567, 934-957

CriticalThe numbers on the dashboard are invented, not measured

globalTokenMetrics is initialised with 524,300 prompt tokens, 289,400 completion tokens and 462 requests — before the gateway has served anything. The usage endpoints multiply those numbers by made-up factors. The log list ships four fake log rows when real logs are empty. There is even a "simulate" endpoint that injects fake traffic into the telemetry.

In plain EnglishThe speedometer is glued to a number someone typed in. It is not connected to the wheels. That feels nice for a screenshot and is poison for decisions.

Example: fresh install, send zero requests, open /api/telemetry. It reports 813,700 tokens and a "money saved" figure. That is not a bug in the UI. It is the design.

Evidence: src/admin/admin-router.ts:53-66, 997-1040, 1045-1174, 1189-1244

High"Zero-drop failover" stops working the moment a stream breaks

Before a stream starts, combos fail over properly. But once a stream is running, a mid-stream error is caught inside the generator and turned into a stream_error event. It does not try the next target. The promise in the README — transparent failover that does not break your IDE session — is only half true.

In plain EnglishIt can change trains before you board. It cannot rescue you when the train stops halfway.

Evidence: src/plugins/combo.ts:276-299 (compare with the working pre-stream loop at 232-274)

HighThe launcher kills whatever is on port 4000. Not just Lattice. Whatever.

Both start.bat and start.ps1 enumerate every process listening on 4000 and force-kill it. src/index.ts does the same on startup with a netstat | findstr :4000 pipe. findstr :4000 also matches :40000. No ownership check, no confirmation.

In plain EnglishIf some other tool is using that port, Lattice murders it and takes the seat. That is not "reclaiming a port". That is collateral damage.

Evidence: start.bat:13-17 · start.ps1:12-23 · src/index.ts:83-95

CriticalThe whole "free" story stands on borrowed ground

The one-click sync reads C:/Users/adity/AppData/Roaming/9router/db/data.sqlite and C:/Users/adity/Videos/cline-proxy-main/.../.cline-accounts.json and imports access tokens and refresh tokens found there. The local store currently holds 12 accounts with plaintext accessToken fields. Some of those accounts have names that are not yours. And the worst part: data/lattice-store.json is tracked by git, with full JWTs and refresh tokens, across 13 commits. Every clone and every fork of this repo carries live credentials in its history.

In plain EnglishThis is the bit nobody writes in the README. A gateway that runs on other people's free-tier logins is not a product yet — it is a technique. And we published the keys to it. That is not a small oops; it needs token rotation and a history scrub, not just a git rm.

Example: the test output printed account IDs like acc_kilo_thelazzycoders_gmail_com and acc_nous_portal_local. Those are real identities in your dev store, your test suite loads them on every run, and git has been keeping a copy since the first commit.

Evidence: git ls-files data · git log -- data/lattice-store.json (13 commits) · src/pool/storage.ts:65-71 · src/admin/admin-router.ts:574-703

But before you get sad: the core engine is actually good. The plugin seam is clean, the dialect work is real, and our take on context-aware combo routing does sharper token math than anything in the three rivals (9router has a broader capability-tier version, which we should borrow). We keep the engine. We throw away the costume.
02

What Lattice actually is

Forget the markdown for a second. Here is the machine, described the way you would explain it to a friend who vibecodes.

Lattice is a local switchboard for AI coding tools. Claude Code, Cursor, Kilo, Roo, OpenCode — they all speak slightly different dialects of "give me a language model answer". Lattice sits in the middle, speaks all of them, and forwards each request to whichever upstream account is still alive. When one provider says "429, slow down", Lattice tries the next one. That is the whole idea, and it is a good idea.

Coding toolClaude Code / Cursor / Roo

→
Resolver + combospick a live target
→
Plugin + account poolkilo / nous / cline / …
→
UpstreamSSE stream back to the tool

← the arrows are the product. Everything else is furniture.

The immutable core

HTTP server (Hono on Bun), three ingress dialects, a canonical request/response shape, streaming adapters, an XML-tool-call interceptor, token counting, timeouts, error normalisation. This part is genuinely reusable.

src/core/* · src/engine/dialect/* · src/utils/*

The plugin layer

Seven plugins: Kilo, Nous, Cline, OpenCode, DeepSeek, FreeLLMAPI and the virtual-combo engine. Each implements one interface: list models, execute, executeStream, health check. Adding a provider should mean one new file.

src/plugins/* · src/core/types/plugin.ts

The pool layer

Accounts with round-robin, cooldown on 429, quota tracking, "retry-after" parsing (including natural language), a proxy pool, and virtual combos that chain targets in priority order.

src/pool/*

The admin layer

A large single-file dashboard with tabs for accounts, combos, models, quotas, logs, telemetry, harness setup and OAuth flows. Impressive volume. Currently also the source of most of the lies.

src/admin/*

03

The amazingness (yes, there is a lot)

I am not here to dunk. Some of this is legitimately good engineering — measured against real competitors, a few pieces are better than what they ship.

1. The plugin seam is real

ProviderPlugin is a small, honest interface. The router does not know anything about Kilo cookies or Cline refresh tokens. That is the single best architectural decision in the repo, and it is why the project can still be saved without a rewrite.

2. Dialects are translated, not faked

Normalizers and serializers for OpenAI Chat, Anthropic Messages and OpenAI Responses, plus SSE adapters that emit canonical events. Thinking deltas, tool calls and usage are first-class in the canonical type. Most small gateways just forward JSON and pray.

3. The XML tool interceptor

Models that emit <tool_call><function=…> as plain text get converted into real tool-call events mid-stream, with a 4 KB fail-safe flush and a partial-parse recovery at stream end. That is a gnarly problem solved properly.

src/engine/dialect/xml-tool-interceptor.ts:120-295

4. Context-aware combo routing

Combos do not just try the next provider. They estimate the prompt with a real BPE tokenizer, look up each target's context window, skip targets that cannot fit, clamp max_tokens to the headroom, and fall through on context-overflow errors. 9router has a broader capability-tier version; ours is the sharpest of the four on exact context-fit math. Keep that edge and add their capability scoring.

src/plugins/combo.ts:100-209

5. Real token counting at the edge

gpt-tokenizer counts messages, system prompts, tool schemas and content parts before forwarding. Even with its rough image baseline, this is more rigorous than "characters divided by four".

6. Harness auto-configuration

One API call writes correct provider blocks into seven different coding tools, with timestamped backups. It is a genuinely lovely onboarding trick. It just needs a lock and a confirmation dialog before it earns its place.

7. The test matrix is unusually serious

527 tests across 63 files, with tiers for boundary cases, combinations, and real IDE-shaped scenarios (Cursor loop, Claude Code thinking + tools, XML recovery, 429 marathon). The tests are better than the product around them.

8. The idle-timeout wrapper

Races upstream iterator.next() against idle and total-request deadlines, cleans up listeners and closes the iterator in finally. Small, careful, correct. This is the standard the rest of the repo should be held to.

9. Intra-model rotation

On a 401/429, Kilo and Nous do not just jump providers — they retry the same model with the next account in the pool, updating cooldown state. The mock-upstream tests actually exercise it. This is subtly different from cross-provider failover, and it is the right first move for keeping a session coherent.

src/plugins/kilo.ts:717-1008 · tests/unit/intra-model-rotation.test.ts

The engine is the asset. Keep it. Everything else in this report is about giving the engine an honest body.

Security & trust boundary

CriticalNo authentication on ingress or admin

No API key check on /v1/*. No session or token check on /admin or /api/*. CORS defaults to * and allowHeaders: ['*']. Binding defaults to loopback, which helps, but browser-based DNS rebinding and any machine on the same network when host is changed both walk straight in.

In plain EnglishThe dashboard and the credential drawer use the same lock: none.

src/core/config.ts:41 · src/core/server.ts:53-63 · src/core/router.ts:56-57

CriticalOAuth status leaks full credentials

/api/oauth/status returns account: session.account, a complete StoredAccount including accessToken / refreshToken. Session IDs are oauth_<provider>_<timestamp> — guessable if you know roughly when someone logged in. Nothing cleans up old sessions.

In plain EnglishThe "are we there yet?" endpoint also hands over the house keys and never forgets a conversation.

src/admin/admin-router.ts:69-84, 554-569

CriticalSecrets sit in plaintext and writes are not atomic

save() uses synchronous writeFileSync to one JSON file with no temp-file-and-rename, no file mode restriction, and no encryption. Every admin mutation calls it. Two concurrent mutations can interleave. Worse: the file is already tracked in git, containing full JWTs and refresh tokens across 13 commits. Deleting it now does not remove it from history — that needs rotation plus a history scrub. Note the inconsistency: harness-manager.ts:58-60 gets atomic tmp-write-and-rename right, the credential store does not.

In plain EnglishAll the keys live in one unlocked notebook, two people writing in it at once can tear the page, and somebody already photocopied the notebook into thirteen public snapshots.

src/pool/storage.ts:62-74 · git ls-files data · harness-manager.ts:58-60

HighHardcoded API key in source

FREELLMAPI_DEFAULT_KEY is a literal string in src/plugins/freellmapi.ts:19-21. If it is real, it is already public. If it is not real, it is still teaching the wrong habit. The harness configs also hardcode sk-lattice-master into seven tools — a token the gateway never actually checks.

In plain EnglishA key typed into source code is not a secret. It is a sticker on the window.

src/plugins/freellmapi.ts:18-21 · src/admin/harness-manager.ts:366-624

HighUnauthenticated endpoints rewrite your other tools' config

/api/harness/setup and /api/harness/setup-all call configureHarness, which overwrites ~/.claude/settings.json, VS Code settings.json, Cursor settings, OpenCode config, Kilo config, Gemini and Crush config. Backups are made, which is kind, but there is no confirmation, no diff preview and no caller check.

In plain EnglishThe helpful button is also a loaded gun. Point it at the wrong request and it rewrites your editor for you.

src/admin/admin-router.ts:934-957 · src/admin/harness-manager.ts:661-693

HighUncaught errors leak their message to the client

The global error handler puts err.message into the 500 response. Upstream fetch errors can include URLs, query strings and headers. A stack-free leak is still a leak.

In plain EnglishWhen something breaks, the gateway tells the caller exactly how it broke, including details meant for you only.

src/core/server.ts:87-95

MediumProbe endpoints can spend your credentials

/api/models/probe and /api/models/:id/test accept an arbitrary model and prompt and send a real upstream request with stored credentials. Unauthenticated, that is a free inference proxy for anyone who can reach the port. The "authentic measurement" shown in the model catalog is also Math.random() latency, not a probe.

src/admin/admin-router.ts:905-920 · src/admin/models-catalog.ts:1261-1271

HighSSRF: anyone can point a provider at an internal address

Unauthenticated POST /api/accounts accepts any credentials object, including a custom baseUrl. The OpenCode plugin uses that URL directly for every upstream fetch and returns the response body to the caller. A cross-origin page can set baseUrl to http://169.254.169.254/ (cloud metadata), to an internal service, or back to http://127.0.0.1:4000/admin, then send a chat request through that "provider" and read what comes back.

In plain EnglishThe attacker does not need to break in. They just fill in the "where should this provider send traffic?" box with an address only you can reach, and ask Lattice to fetch it for them.

src/admin/admin-router.ts:174-204 · src/plugins/opencode.ts:448-453, 515-534

HighStored XSS in the admin dashboard

The account table interpolates a.id, a.providerId, email, apiKey and accessToken straight into tbody.innerHTML. Since account creation is unauthenticated, an attacker can plant a crafted id or email that executes script in the admin origin. From there every control API is reachable. The whole UI is one inline script with no Content-Security-Policy, so there is no second line of defence.

In plain EnglishSomeone can write a poisoned name into the address book that, when you open the dashboard, runs their code as if you had typed it.

src/admin/dashboard-ui.ts:2760-2775, 3849 · src/admin/admin-router.ts:174-204

Correctness & behaviour

HighFailover gives up when a stream dies halfway

The streaming combo loop returns a generator. Inside it, a thrown stream error is converted to a stream_error event rather than rethrown, so the outer for (const target of combo.targets) loop can never see it. No second target is tried. The non-streaming path does fail over correctly.

In plain EnglishFailover works at the starting line, not at the finish line. Agents stream. This matters.

src/plugins/combo.ts:276-299

HighToken usage is charged to the wrong account

recordProviderUsage attributes usage to the active account with the newest lastUsedAt — but getNextRotatedAccount also writes lastUsedAt at selection time, and concurrent requests share that field. Under rotation or load, quota and token numbers drift away from the account that actually did the work. The streaming path logs status: 200 in finally even when the stream failed or timed out.

In plain EnglishThe accountant charges the receipt to whoever touched the pen last, not who bought the thing.

src/pool/account-pool.ts:106-117, 360-386 · src/core/router.ts:293-312, 418-437

HighDisabling a plugin does not fully disable it

The router's resolveProvider checks only plugins.has(providerId), not isEnabled(). Combo resolution has a similar split: prefix resolution uses registry.has() while the catalog fallback uses getEnabled(). The admin toggle therefore changes badges, not always behaviour. The existing model audit also verified that turning every plugin off still returns all 64 catalog entries.

In plain EnglishThe on/off switch is connected to a light bulb, not to the machine.

src/core/router.ts:181-199 · src/utils/model-resolver.ts:50-69 · crush_model_report.md:92

Medium/v1/responses never streams

The Responses route always calls provider.execute and returns one JSON object. If a client sends stream: true, it gets a single blob. The other two dialects have full SSE pipelines.

In plain EnglishOne of the three advertised front doors is boarded up.

src/core/router.ts:461-503

MediumContext windows are guessed from model names

getModelContextWindow falls back to string matching: if the model id contains 1m, opus, sonnet, ernie-5.5, ling-3.2 and so on, it claims 1,048,576 tokens. Routing decisions — which target to skip, how much to clamp max_tokens — are made from that guess.

In plain EnglishThe router decides how much luggage fits by reading the label on the suitcase, not by measuring it.

src/plugins/combo.ts:58-75

MediumOne plugin means any model routes anywhere

If exactly one plugin is registered, resolveProvider returns it for every model without checking its catalog. Convenient for the mock-provider tests, surprising in a real single-provider deployment.

src/core/router.ts:156-160

MediumCatalog cache is stale for 60 seconds

getModelPluginMap caches for 60s and swallows per-plugin failures. A newly added account or a temporarily failing plugin can leave a model unroutable (or wrongly mapped) until the cache expires. Bare-name aliases are inserted only when unambiguous at build time — but later plugins can overwrite them.

src/core/router.ts:86-121

HighNon-streaming requests have no deadline at all

Only streams get withIdleTimeout. All three provider.execute() calls are bare awaits. A hung upstream holds the request until Bun's socket idle timeout (255s), and under load that exhausts connections. A configuration key called requestTimeoutMs exists but is never applied here.

In plain EnglishStreams have a watchdog. Normal requests have a wish.

src/core/router.ts:235, 360, 482 · src/index.ts:73

High"Retry-After" as a date poisons an account forever

RFC 7231 allows Retry-After to be either seconds or an HTTP date. Kilo and Nous parse it with Number(header || 10). On a date, Number('Wed, 18 Nov 2026 ...') is NaN, so cooldownUntil = NaN. Every auto-heal comparison against now is then false, so the account sits in cooldown permanently until someone resets it by hand. The pool quietly shrinks.

In plain EnglishOne provider writes the "come back at 3pm" format instead of "wait 30 seconds", and Lattice puts that account to sleep forever.

src/plugins/kilo.ts:773-776 · src/plugins/nous.ts:751, 859 · src/pool/account-pool.ts:50, 86, 258

MediumAborted streams leak upstream connections

parseSSEStream calls reader.releaseLock() in finally but never reader.cancel(). The idle wrapper calls iterator.return?.() but does not abort the underlying Response.body, and the SSE parser is called without the abort signal. A client disconnect or 504 leaves upstream bodies open. Buffers and sockets accumulate under churn.

In plain EnglishWhen you hang up, the gateway keeps the other phone off the hook. Do it a thousand times and the switchboard is full of dead calls.

src/utils/sse-parser.ts:127-129 · src/utils/idle-timeout.ts:119-127 · src/engine/dialect/stream-adapter.ts:266-269

MediumTwo registries, three resolvers, one duplicate combo plugin

The router resolves through the startup plugins Map; the combo engine resolves through globalPluginRegistry. Separately, the admin router registers a second LatticeComboPlugin under key lattice-combo while its own .id is lattice. Result: duplicate catalog entries, toggle state applied to one registry but not the other, and three different answers to "which plugin serves this model?".

In plain EnglishThere are three filing cabinets with slightly different copies of the same address book. Nobody knows which one the postman reads.

src/index.ts:27, 45 · src/admin/admin-router.ts:142-144 · src/core/router.ts:144 · src/utils/model-resolver.ts:50 · src/plugins/combo.ts:35

MediumRuntime cooldown/quota state vanishes on restart

reportRateLimit() and recordTokenUsage() mutate in-memory state. globalStorage.save() is called only from admin mutations, never from the request path. Restart the gateway and rate-limited accounts wake up active and get hammered again, while persisted quotaRemaining stays stale.

In plain EnglishThe memory of who was tired is forgotten every time you turn the machine off, so the gateway immediately makes them work again.

src/pool/account-pool.ts:141-162, 331-386 · src/pool/storage.ts

MediumNo request body limit; double load at startup

Zod validation happens only after the entire JSON body is buffered, with no Content-Length cap — a single large base64-image request can exhaust memory. Separately, the store is loaded twice (constructor plus explicit call in index.ts), and addAccount overwrites updatedAt on every load. Two smaller wastes: an unused estimatePromptTokens import in the router, and a TransformStream constructed then thrown away on every request because only its .transform() generator is used.

In plain EnglishAnybody can hand the gateway an enormous suitcase and it will try to carry it. Meanwhile it reads the same notebook twice on purpose.

src/core/router.ts:217, 342, 466 · src/pool/storage.ts:23 · src/index.ts:18 · src/engine/dialect/xml-tool-interceptor.ts:337

HighPersonal paths and personal accounts baked into the product

Two absolute C:/Users/adity/... paths in the sync endpoint. The store has 12 accounts including emails that are not yours. Test runs print those identities to the console. For an open-source project this is both broken (sync does nothing on anyone else's machine) and a privacy problem.

In plain EnglishThe "one-click import" button is wired to one specific laptop. On yours it is a decorative button. On that laptop it is a data vacuum.

src/admin/admin-router.ts:579, 656

bin/lattice.exe is staged for deletion while lattice.exe sits at the root. README says 382 tests / 49 files; reality is 527 / 63. bun run typecheck fails on the new FreeLLMAPI plugin (missing checkedAt, wrong stream event type). The dashboard is a ~95 KB inline script inside a TypeScript template literal — a single mis-escaped quote kills every button, which is why a special guard test exists.

In plain EnglishThe map is older than the territory, and the smoke alarm is taped to the wall on purpose because it keeps going off.

package.json:13-16 · README.md:111 · TEST_INFRA.md:110-116 · tsc output

MediumFreeLLMAPI is a hard local dependency with a fake catalogue

The plugin defaults to http://127.0.0.1:31415/v1. If that app is not running, the plugin falls back to seven hardcoded model descriptors that claim 1M context and isFree: true regardless of reality. Its streaming path emits fallback usage numbers (15 prompt / 20 completion) when upstream gives none. Combo targets include those descriptors.

In plain EnglishA core part of the "1M free" promise is a placeholder that pretends to be a live provider when the real one is asleep. Meanwhile the real upstream project (53,958 stars) ships AES-256-GCM encrypted keys, in-flight quota leases to fix race conditions, an Ed25519-signed model catalog, and honest "available: false" flags. We copied its endpoint and its key format. We did not copy any of the engineering that makes it work.

src/plugins/freellmapi.ts:18-21, 83-226, 308-311, 435-443 · upstream: github.com/tashfeenahmed/freellmapi

MediumThe catalog drifts away from reality

An existing audit in the repo (crush_model_report.md) found 6 phantom models in /api/models that no serving plugin can handle, 21 entries counted as free that are not, hardcoded dashboard numbers ("6 with 1M context" when the API has 15), and 36 Crush entries whose context window is an invented default. That audit is dated 17 Nov 2026 — yesterday.

In plain EnglishThe shop window lists six items the kitchen cannot cook, and the price tags are guessed.

crush_model_report.md:9, 88-100

Drift: how a good engine ended up wearing a costume

I read the git log like a doctor reads a temperature chart. The pattern is not random. It is the pattern of building fast and then patching the cracks with more paint.

17 Nov 2026 · 00:06

"resolve opencode multi-turn serialization, restore 9router-style providers view with authentic logos, and ensure standalone independence." Three different concerns in one commit: a routing fix, a UI imitation and a packaging goal. That is drift in a single sentence.

Earlier that day

"audit context windows, free providers catalog, token usage and quota tracker views" — adds views. The audit itself later lands in crush_model_report.md saying the numbers are stale.

A few commits back

"resolve in-browser script parse SyntaxError and verify UI in headless Edge", then "resolve JS syntax errors in client template string preventing tab and modal clicks", then "true SPA tab navigation" and "bulletproof event delegation". Four commits fixing the same fragile 95 KB inline script. Symptom, symptom, symptom, symptom.

More recent history

"complete human-engineered UI rebuild, free models explorer & 1-click harness setup" — a lot of surface area, built while the core still had no auth and no real telemetry.

Right now

27 modified files, +2,874 / −939 lines uncommitted. New files include a token estimator, idle timeout, intra-model rotation tests and a FreeLLMAPI plugin that does not typecheck. The work is good. The integration is unfinished.

Two extra tells: the README still advertises proxy rotation and uTLS, neither of which exists in src/. And one of the 527 tests asserts that the account-creation endpoint returns the full credentials — the leak is not just untested, it is locked in by a passing test.

The drift loop, drawn honestly

1 · Build

A real engine feature

Combos, dialects, pool. Usually solid.

2 · Decor

Hardcode a demo number

"6 models", "813,700 tokens", 0.36 provider shares.

3 · Drift

Reality moves on

Providers change, catalog grows, numbers rot.

4 · Patch

Fix the label, not the source

Another syntax fix, another UI rebuild.

The exit from this loop is not "more discipline". It is making the UI derive every number from a measured source so lying becomes structurally impossible.

The uncomfortable sentence

The most damaging line of code in this repository is not a bug. It is the initialiser at src/admin/admin-router.ts:53-66 that writes fake telemetry into global state at startup. It taught the whole dashboard to lie, and every "fix" since has been decorating the lie.

The unbeatable thesis

You said: no hundreds of providers, no roulette where every message goes to a different model. Good. That constraint is the strategy. Here is the thing I would actually try to build.

The one-sentence product

Lattice is the gateway that tells the truth about models and keeps an agent on one model until it is safe to move. Everything else is in service of that sentence.

The four pillars

1. The model passport

On first use — and on a schedule — send a tiny standard probe to every target: tool calling, structured JSON, thinking, image input, a 32K and a 200Kcontext stretch. Store a signed passport: measured_context, tool_accuracy, json_validity, ttft, stream_stability. Routing reads the passport, never the marketing name. The existing context-window lookup becomes the first, crude version of this. Prior art to build on: 9router's capability-tier ordering and FreeLLMAPI's signed catalog — combine them, then add our tokenizer-driven context fit and per-model scores. That combination is the new part.

2. Session continuity with safe handoff

A task gets pinned to one provider + model + account. On a 429, first rotate accounts within the same model. Only at a turn boundary do you consider another model, and when you must, Lattice writes a short structured handoff summary into the conversation so the new model continues the same mind. No mid-sentence jumps, no personality whiplash. Bonus from the Rust Cline proxy: derive a stable task id from an HMAC of session + chosen key and canonicalise tool-argument JSON, so long contexts keep their prompt-cache hits (that project measured 99.8–100% on a ~300K-token session). Continuity and cache locality are the same idea.

3. The receipt ledger

Every request produces a small append-only record: request id, chosen target, actual account (hashed), real tokens, latency, outcome, failover events. Hash-chain them so they cannot be quietly edited. The dashboard reads only the ledger. Fake telemetry becomes impossible because there is no other source to read.

4. The dialect conformance suite as a public good

Publish the canonical translator as a standalone library with a public conformance page: "here are 200 real Anthropic/OpenAI edge cases and how we translate each." If Claude Code, Roo and Cursor behave correctly through Lattice and break through others, developers will pick Lattice for the translator alone. That is a moat you can ship.

Notice what is missing from this plan: "add 100 providers". A passport makes any provider plug in correctly. Twenty well-measured providers beat two hundred unmeasured ones.

What "unbeatable" would actually mean

Not "most stars". Not "most models". It means: a developer installs Lattice once, points seven tools at it, and never has to think about it again. When something breaks, they get a receipt that explains why, a fallback that preserved their session, and a fix that arrives before they notice. That is the bar. It is hard. It is possible. It will not be done in one night — and that is fine.

A fresh clone, on a fresh machine, with no personal paths and no credentials, starts, typechecks, passes all tests, shows zero tokens in the dashboard until you send a request, and cannot be controlled by a web page you happen to visit. That is a real v1.0.

Coming inventions: the stuff that should blow minds

Not today's roadmap. These are the "maybe we fail, but if we don't, nobody has this" ideas. I will tell you which are plausible and which are wild.

A. The flight recorder

Plausible · high value
Every canonical event for every request is stored, replayable against any plugin. A bug report becomes "here is the exact stream, run it again". Debugging agent failures stops being archaeology.

B. Quota as a scheduler

Plausible · genuinely new
Treat accounts, quotas and reset times like a compute cluster. Ask for "a 400K-token task finishing in 10 minutes" and Lattice reserves capacity across providers, with an ETA and a plan. Nothing else does this.

C. Consentful quota commons

Wild · ethically important
Instead of silently importing other people's accounts, build an opt-in protocol: I share my spare quota, I see exactly who used it, I can revoke instantly, and the gateway gives me credit when mine is used. Turns the current legal liability into a feature.

D. The gateway as a test harness

Plausible · developer magnet
Point a model at Lattice, run "conformance", get a scorecard of tools, JSON, thinking, streaming and context. Vendors would run it. Your scores become the reference everyone cites.

E. A tiny DSL for combos

Plausible · power-user lock-in
Today combos are a flat array. A small language — prefer model where json_valid > 0.9 within 400ms else … — makes routing programmable. Ship it with a visual editor in the dashboard.

F. Local model mesh

Wild · long horizon
Let Lattice route part of a task to a small local model for the boring 80% and a frontier model only where the passport says it is needed — with continuity preserved by the handoff layer. Privacy plus cost, without model roulette.

G. Compaction as a first-class gateway service

Plausible · borrow and improve
The Go Cline proxy ported an anchored summary template (Objective / Important Details / Work State / Next Move / Relevant Files) from the official client. Move that into Lattice: when a context fills up, compact at the gateway with a deterministic template, persist the summary, and keep the last N messages verbatim. Threshold should be context − max(output, 80000), because some clients cap input at 128K and never trigger compaction with the naive formula. This makes handoff between models actually work.

Pick one. Not six. If I had to choose, it is C paired with B: make the sharing honest, then schedule it like a cluster. That is a company, not just a repo.

Phase C2 — continuity without hidden memory

  • Opt-in session pinningx-lattice-session is hashed immediately; the gateway stores no raw session id, prompt, message, or tool payload.
  • Cache-local target continuityRepeated turns try the successful combo target first. Separate sessions keep separate pins, and configured combo order is never mutated.
  • Account before model rotationKilo, Nous, Cline and DeepSeek prefer the session's healthy account, rotate within that provider/model when needed, then repin the successful account.
  • Bounded and disposableAffinity is memory-only, expires after 30 idle minutes, and is capped at 10,000 sessions. Restarting the gateway clears it.
  • No stitched turnsPre-content stream failure may repin a fallback; after content begins, Lattice reports the failure and does not switch models.

  • Executable public fixturesOpenAI Chat, Anthropic Messages and OpenAI Responses requests run through the real normalizers and serializers with literal semantic expectations.
  • Streaming checked honestlyChat and Messages SSE event semantics are exercised. Responses streaming was later implemented and its conformance fixture now verifies the real event sequence instead of a fabricated pass.
  • Deterministic evidencebun run conformance writes stable machine-readable results to conformance/results.json without provider calls.

Phase C4 — no more silent sync

  • Hardcoded paths deletedThe old sync-local endpoint read two personal absolute paths and embedded email addresses in account IDs. It is removed entirely.
  • Consent before importAn operator supplies an explicit export path. Preview returns only provider names, a count, and a 60-second token; no token, email, or raw account ID is exposed.
  • Opaque identities and separated secretsImported accounts get random IDs and their secrets go to a dedicated 0600 file with an honest file-fallback availability label.
  • Single-use, digest-bound confirmationA tampered, reused, or expired token cannot import. A behavioral test proves an unsafe baseUrl in an export cannot become an account credential.

Phase C5 — imported accounts actually work

  • One credential seamA single resolver overlays secret-store values onto account credentials at each plugin read site. The account object is never mutated, so secrets cannot leak back into the tracked-format store.
  • Imported accounts are liveKilo, Nous, Cline, DeepSeek, OpenCode and FreeLLMAPI all resolve credentials through the store for acc_import_ accounts. An end-to-end test proves a store-only apiKey reaches the outbound Authorization header.
  • Refresh writes throughCline and Nous token refreshes update the secret store, so a refreshed token is never shadowed by the old one.

Phase C6 — secrets in the operating system, not a file

  • Real OS backendsWindows DPAPI, macOS Keychain and Linux libsecret sit behind the same SecretStore interface. The Windows path encrypts secrets for the current user account via PowerShell ProtectedData.
  • No fake labelsA backend is reported as keychain or os-dpapi only after a probe passes. Any failure falls back to the 0600 file and reports file-fallback.
  • Lazy and opt-inNo OS command runs at import time. The OS backend activates only with LATTICE_SECRET_BACKEND=keychain; the availability probe is cached so the admin endpoint does not spawn processes per request.

Phase C7 — the passports learn from reality

  • Passive measurementA real tool call, thinking block, accepted stream, or context-overflow error upgrades a claim from declared to measured in the signed record. No extra provider call is made.
  • No false negativesAbsence of a tool call is never recorded as "tools unsupported". Only positive evidence and conservative overflow bounds become claims.
  • Stable under loadIdentical observations are deduplicated, and catalogue refreshes cannot downgrade measured evidence. The global store keeps independent instances per data directory.

Phase C8 — rotation that cannot repeat a tool call

  • Ambiguous failures fail fastA network error, timeout or abort now returns 502 immediately in Kilo, Nous and Cline instead of trying another account. The upstream may have processed the first request, so a retry could duplicate a tool call or a charge.
  • Provably safe switches remain429 rate limits and 401/403 auth rejections still rotate, because those responses prove the request was never processed. A test counts fetch attempts for each case.

Phase C9 — closing the deferred minors

  • Bodies bounded for realRequests without a declared Content-Length are byte-counted while streaming and rejected at 413, closing the chunked-body bypass.
  • Deadlines stop workA timed-out request now aborts its upstream fetch instead of merely returning early and leaving a connection open.
  • Bounded combosTarget attempts are capped in both non-stream and stream paths, with an off-by-one corrected.
  • Honest numberstokensPerSec now divides tokens from the same window as its time span, and one labelled illustrative USD rate feeds both the API and the dashboard.

## Part 3 — New-code review (ranked findings)

Verified with `bun findings.ts` scratch scripts by the independent new-code reviewer; top two re-checked by reading source directly.

1. **High — combo skip paths leak a half-open breaker probe.** `src/plugins/combo.ts:199,215,223` and `:349,365,373,419`; `src/core/breaker.ts:96,106,111`. `beginAttempt()` sets `probeInFlight=true` on a half-open breaker; context-overflow, exhausted-quota and empty-stream `continue` paths never call `cancelProbe()`, `recordSuccess()` or `recordFailure()`. `allow()` then refuses forever because it checks `probeInFlight` before the clock. No admin reset path. Repro output: `AFTER skip: state=half-open allow=false retryDelay=0`; second request `stubCalls=0`. Confirmed by source read of combo.ts:199–223.
2. **High — streaming success recorded before delivery; breaker can never open on mid-stream deaths.** `src/core/router.ts:214-218,262-267`. `reportProviderSuccess()` fires when `executeStream()` resolves (headers), then a `stream_error` increments failures; each request resets then increments, so `failures=1` forever. Repro: `request 1 … request 6: state=closed failures=1 allow=true`.
3. **Medium — all-target circuit-broken/unresolvable combo reports 400 `context_length_exceeded`.** `src/plugins/combo.ts:196,278-285,345,496-503`. Breaker skips are counted as context overflow; client is told to shorten the prompt when the provider is down.
4. **Medium — combo traffic loses account attribution.** `src/plugins/combo.ts:234-238`, `src/core/router.ts:184-188,275-279`. Plugins set `accountId` on a copied request; the router's outer request never sees it, so ledger/receipts record provider `lattice`, serving account quota never moves, and `hasQuotaAvailable()` cannot see consumption. Direct-plugin path does attribute — inconsistent between entry paths.
5. **Low/Medium — `isProviderHealthFailure` misclassifies 5xx whose message contains "aborted".** `src/core/breaker.ts:51`. `GatewayError(500,'aborted upstream') → false`; `GatewayError(500,'boom') → true`. `recordFailure()` still cancels the probe.
6. **Low — a rejecting plugin `shutdown` hook aborts the rest of shutdown and process exit.** `src/core/plugin-lifecycle.ts:28-35`, `src/index.ts:118-122`, `bin/lattice.ts:125-129`. No current plugin declares `shutdown`, so latent.

Verified NOT bugs: reservation release on throw/double-release/abort, concurrent `acquireAccount` race (fully synchronous), pricing unknown/estimated handling, router double-counting usage, startup banner secrets (fingerprints only), missing lifecycle hook (fails fast).

## Part 5 — Verdict

Refinement of ADV-5 from Part 4: `src/core/router.ts` never calls `breaker.allow()`. Enforcement happens only inside `globalAccountPool.acquireAccount()` (`src/pool/account-pool.ts:133`) and in combo targets. Controlled re-run with an account registered for the provider (`bun run tests/audit/fixtures/breaker-gate.ts`): `GATE after 6: calls=3 state=open allow=false failures=6`; `GATE after 12: calls=3 state=open allow=false` — provider calls stopped. Therefore the ADV-5 failure applies to plugins/paths that do not acquire an account (custom/keyless/anonymous adapters and direct plugin calls), not to the normal accounted path. Note `failures=6` for 3 calls: router and pool both record the same failure, so the threshold is reached early.

00 — THE VERDICT

A very good engine, wearing a release costume that doesn't fit.

The architecture deserves its confidence. The shipping discipline does not. Those are separate problems and they need separate work.

Lattice is the rare project where the hard part is genuinely done well. The plugin seam is real: providers live outside the router, and adding an upstream does not mean editing core. All three dialects — OpenAI Chat, Anthropic Messages, OpenAI Responses — are first-class, with executable conformance fixtures to prove it. The project even built an epistemology for its own model claims: a fact is labelled declared, discovered or measured, and a signature is never allowed to pretend a guess is the truth. That is a better foundation than most gateways ever get.

And then the same tree still has live OAuth tokens in Git history, a test mock reachable from the default server path, a model catalogue advertising entries nothing can serve, no CI workflow at all, and a README promising an MIT license that no LICENSE file backs up. None of this is an architecture failure. It is the last mile — and right now the last mile is the entire story between "impressive" and "safe to hand someone."

The verdict is not "rebuild." It is "close the gaps in a specific order." That order is the spine of this document.

01 — WHAT IT IS

One port, one core, everything else a plugin.

The pitch is consolidation: replace four fragmented daemons on ports 3457, 20128, 9655 and 8080 with a single gateway on 4000 that speaks every dialect and pools every account.

What actually ships

Account pooling with cooldowns and round-robin; natural-language 429 Retry-After parsing; transparent pre-stream failover across virtual combos like lattice/code-flagship; an append-only request ledger; signed model passports; session affinity that prefers the same model and account before switching; a two-step consent flow for importing accounts; a secret store that admits when it is only a 0600 file; capability learning from real traffic; and rotation that refuses to retry an ambiguous failure. That last one is quietly excellent: a 429 or a 401 proves the request never landed, so switching accounts is safe. A timeout or a 5xx does not, so the gateway fails fast instead of risking a duplicated tool call or charge.

The admin surface at :4000/admin is a single-page mission control with live log streaming, plugin toggles, combo management, a free-model explorer and a model probe. A parse guard exists specifically because that UI is one large inline script — a misplaced quote used to take the whole dashboard down while the page still looked fine.

03 — WHERE IT BLEEDS

Filed cases, not vague concerns.

Every issue below names a file and a line. Ranked by what it costs you if you ship today.

CRITICALCASE 01 / SECURITY

The credentials are still in the history.

SECURITY.md says it plainly: live OAuth tokens were committed inside data/lattice-store.json. Removing the file from the index does not unwrite the commits — anyone holding a clone can still read every token. The exposed tokens predate the current branch state: whether the branch is ahead of origin or in sync with it, the history itself still carries the secret. Rotation and scrubbing are the only remaining moves.

Order of operations

1 Revoke every Kilo, Nous, Cline, DeepSeek and FreeLLMAPI token at the provider. 2 Scrub with git filter-repo --path data/lattice-store.json --invert-paths. 3 Force-push and have collaborators re-clone. 4 Only then add accounts through the consent flow. Rotation is not optional and it cannot be automated from here.

HIGHCASE 02 / HONESTY

Production has a mock switch nobody admitted to.

createServer() imports tests/mocks/mock-provider whenever it is called without plugins (src/core/server.ts:47). DeepSeek's challenge solver returns the literal string ds_session_cookie_mock when verification fails (src/plugins/deepseek.ts:304 and :310). In a harness whose entire position is honesty, a silent fallback to fake providers and fake credentials is the worst possible shape of bug: every light stays green while nothing is real.

Fix

Make both paths fail loudly with an actionable error. Keep the mock behind an explicit test-only flag — the suite depends on that literal, so move it to configuration rather than deleting it. A gateway must never confuse "working" with "pretending."

HIGHCASE 03 / CATALOGUE

A catalogue with exhibits nothing can serve.

CANONICAL_FREE_MODELS still holds Groq and Gemini entries, but no groq or gemini plugin is registered in src/index.ts. getEnrichedModelsCatalog() seeds from that static list and only drops a provider that is explicitly disabled — an unregistered provider is not disabled, so the ghosts survive into /api/models. The earlier audit counted six such phantom models, twenty-one entries flagged free that are not, and a "1M" combo whose seventh target is only 128k.

Fix

Change the participation rule: a model must be served by an enabled plugin to be listed as routable. Label the remainder honestly — routable, discovered, declared, unavailable, virtual. Then delete the phantom static rows. Context windows that come from a guess must not be displayed as measurements.

HIGHCASE 04 / VERIFICATION

Green means green on this laptop.

There is no .github/workflows directory. bun run verify runs typecheck, the dashboard parse guard and 392 unit tests — it skips the other 300 integration and E2E cases and the conformance runner entirely. A fresh clone has no gate, and the command most likely to be trusted is the one that checks the least.

Fix

One command, one truth: typecheck → dashboard parse → conformance → full 692-test suite → compile → smoke-test the binary. Make that the release gate, then make CI run it on every push. A suite that is only green locally is a diary, not a guarantee.

MEDIUMCASE 05 / RELEASE

It says MIT and ships no license.

The README promises MIT; the tree has no LICENSE. package.json is still 0.1.0. bin/lattice.exe was correctly removed from the index and is now gitignored — that was the right call, since a stale 90 MB binary silently serves old code — but there are no release artifacts, no checksums and no changelog. Nothing here is hard. It is all the paper that turns software into a product.

Fix

Add the MIT license. Write a changelog from the four pending commits. Bump the version. Publish the compiled binary as a release asset with a checksum file, and verify a clean-machine start before calling it done.

MEDIUMCASE 06 / DASHBOARD

The numbers flash before they are true.

dashboard-ui.ts still hardcodes "31 Free" into two elements (lines 1384 and 2109); JavaScript replaces them once /api/models resolves. The same file tells readers the explorer includes "verified 1,000,000+ token context models" (line 2514) — but that context is declared by plugins, not verified by measurement. A truth project should not overstate in its own UI.

Fix

Ship neutral placeholders such as "—" and derive every number from the API response. Change "verified" to "declared" unless a probe actually measured it. Small wording, large consistency.

LOWCASE 07 / EDGES

Health arrived; the exits did not.

Liveness probes now exist at /healthz, /health, /api/health and /v1/health. Cooldowns persist to data/account-health.json with Healthy → Cooling → HalfOpen states, and bun run why <request-id> explains a single request from the ledger. That closes a real part of the operational gap. What remains: no documented graceful-shutdown behavior, no general data migration or schema-versioning story, Windows-first packaging, no CONTRIBUTING guide, and a README feature list that jumps from 8 to 10. These are small things; release quality is mostly a pile of small things.

Fix

Fold the remainder into the operational milestone rather than chasing them now. None blocks correctness. All of them block "I would run this for someone else."

04 — THE FIELD

Who else wants this job.

Honest comparison, not a victory lap. Each tool optimizes for a different thing, and two of them beat Lattice at it.

9router is the router people actually reach for when they want many free providers behind one key. Its strength is breadth and low setup friction: a provider registry, key management, load balancing and failover in a mature release cycle. Lattice's own admin already borrows its "providers view with authentic logos" idea — flattering, and a reminder that good interface ideas travel. Where 9router wins is the boring, decisive category: releases, onboarding, number of live providers. Where it does not compete is what Lattice treats as first-class — signed evidence about what a model can do, or carrying one conversation identity without storing its content.

FreeLLMAPI is the upstream, not a peer. It is a local aggregator exposing a large free-model catalogue — hundreds of routes — on a machine's loopback. Lattice consumes it as one plugin; the two are complementary. If the measured goal is "how many free models can I see," FreeLLMAPI wins outright, and Lattice should stop pretending to out-catalogue it. Its value is turning that raw catalogue into something a client can trust and a session can survive.

cline-proxy is the small, sharp tool: rotate Cline accounts, dodge rate limits, keep working. One client, one problem, tiny surface. It beats Lattice on focus — there is far less to misconfigure, and every line of code serves the single job. Lattice generalizes the same rotation idea across every plugin, adds dialect translation and failover, and pays for it in complexity. That complexity is a feature when you need it and a tax when you don't.

Where Lattice loses

Setup friction, live provider breadth and release maturity. FreeLLMAPI has more models than Lattice will ever hand-maintain. 9router has the polish that comes from years of shipping. cline-proxy has the luxury of one job. If the goal is "get a free endpoint into Cursor in five minutes," those tools win today.

Where Lattice wins

Nobody in this set treats truth as a subsystem. Passports separate a declared claim from a measured one. Session affinity remembers a conversation without storing it. Import asks permission and hands back a digest, not your account list. Rotation distinguishes "never landed" from "may have landed." Those are not checklist features — they are a position.

The honest line

Lattice is not a better 9router. It is a different animal: a harness for people who care what the gateway believes, and why. The price of that position is surface area — and surface area is exactly where the cases in chapter 03 live.

05 — THE MOAT

The things that would be missed if you copied the rest.

Features are easy to clone. A posture is not. These are the pieces that make Lattice more than the sum of its plugins.

01 / TRUTH

Model passports

Claims carry an evidence class — declared, discovered, measured — and an Ed25519 signature over a canonical record. The documentation says outright that a signature proves integrity, not truth. That admission is the whole design.

02 / LEARNING

Passive capability learning

A real tool call, thinking block or context-overflow error upgrades a claim from declared to measured. No extra provider call, no negative claim, no rewriting the file for identical observations. Catalogue refresh cannot downgrade a measurement.

03 / CONTINUITY

Session affinity without storage

A hashed, in-memory pin keeps a conversation on its target and account. Thirty-minute idle expiry, a 10,000-session cap, no prompts retained, no persistence across restarts. A routing optimization that refuses to become a history database.

04 / CONSENT

Import that asks first

Preview returns only a provider list, a count and a short-lived token. Confirmation is single-use and bound to the preview digest. Accounts get opaque IDs and their secrets live in a separate 0600 file. No hardcoded local path, ever.

05 / SAFETY

Honest rotation semantics

Only a 429 or an authentication rejection may switch accounts, because those prove the upstream never processed the request. Network errors, timeouts, aborts and 5xx fail fast. The gateway will not gamble with a repeated charge.

06 / HONESTY

Secret storage that admits its limits

A narrow interface with a real file fallback. OS-backed keychains are opt-in and probe-gated: Windows DPAPI, macOS Keychain, Linux libsecret. If the probe fails, the gateway reports file-fallback instead of wearing a badge it did not earn.

07 / PROOF

Executable conformance

Fixtures run through the real normalizers, serializers and stream adapters with no network access, writing deterministic results. A conformance badge backed by a runner, not by hand-written expectations.

08 / SHAPE

A seam, not a pile

Adding a provider is a plugin, not a patch to core. Dialect translation, XML recovery and combo failover stay untouched. That is why the project can keep improving its trust layer without renegotiating every upstream.

09 / RECEIPTS

An answer for every request

bun run why <request-id> reconstructs one request from the ledger — outcome, provider, model, latency and token accounting, with estimates labelled. Account cooldowns survive a restart in a file that carries no secrets, moving through Healthy, Cooling and HalfOpen.

06 — WHAT IT BECOMES

The order matters more than the ambition.

Five milestones, each with a definition of done. Do them in this sequence and nothing later has to be redone.

0

Close the wound

Resolve the credential incident before anything is pushed or published.

Done whenEvery exposed token is revoked, the store is gone from history, the remote is force-pushed, collaborators have re-cloned, and accounts have been re-added through the consent flow.
1

Release hardening

Turn a local success into a repeatable, verifiable artifact.

Done whenMock fallbacks fail loudly; the catalogue only lists served models; one gate runs typecheck → dashboard parse → conformance → all 692 tests → compile → binary smoke test; CI runs it on every push; LICENSE, changelog and version bump exist; a signed checksummed binary starts on a clean machine.
2

Operational backbone

Make it something you can leave running for someone else.

Done whenHealth probes, receipts and persisted cooldowns already ship — keep them honest; add structured metrics for rotation and failover decisions, a general data versioning and migration story, graceful shutdown that drains in-flight requests, and packaging beyond Windows.
3

Catalogue convergence

Let the evidence layer become the authority it was designed to be.

Done whenStatic phantom rows are deleted; live discovery populates declared claims; passports decide context and capability; every UI number is derived; nothing is called verified that was only declared.
4

Distribution

Borrow the maturity of the field without borrowing its posture.

Done whenReleases are signed and documented; onboarding is as frictionless as 9router's; the answer to "why not just use a router" fits in one paragraph. A remote signed catalogue stays a deliberate non-goal until local measurement covers it.
Why this order

Catalogue work before the gate means you keep re-verifying a moving target. Release work before the credential fix means you distribute the incident. Sequence is the cheapest form of engineering judgement available here.
